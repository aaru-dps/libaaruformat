Detailed Description

Twin sectors: several physical sectors answering to the same sector address.

Twin #0 is stored as any other sector. Twins #1..n-1 are kept in memory as TwinInstance records (one value per component: user data, CD prefix/suffix, subheader, subchannel, DVD/BD long-sector fields, Apple/Priam tags) and serialized into a single twin sector table block (TWTB) when the image is closed.

To avoid duplicating the decomposition/recomposition logic of the long-sector and sector-tag functions, a twin operation temporarily "swaps" the twin's components into the per-sector storage slots of the address, runs the normal function, captures the resulting slot values back into the twin (write) and restores the slots of twin #0. User data is redirected through ctx->twin_write_* (write) and ctx->twin_read_* (read), which aaruf_write_sector() and aaruf_read_sector() honour.

Same contract as aaruf_write_sector(). twin_index 0 is exactly aaruf_write_sector().

  • twin_index < count: replaces that instance.
  • twin_index == count: appends a new instance.
  • twin_index > count: AARUF_ERROR_TWIN_INDEX_OUT_OF_RANGE.

Twins do not contribute to the image checksums, which are computed over twin #0.
