Detailed Description

On-disk structures of the twin sector table (TWTB) and the public enumeration record.

Some media carry more than one physical sector answering to the same sector address ("twin sectors"), for example floppies with duplicated sector IDs or CDs where the same MSF appears more than once.

Twin #0 is stored exactly like any other sector (user-data DDT, CD prefix/suffix DDTs and arenas, per-sector tag arrays). Its user-data DDT entry carries status SectorStatusTwin, but its pointer still references twin #0's data so readers unaware of twins transparently read twin #0.

Every further instance (twin #1..count-1) is a TwinInstance record inside the TWTB. A record holds one value per component declared in the table header: user data and CD prefix/suffix are stored as pointers using exactly the same encoding as their respective DDTs (status in the high nibble), small fixed-size tags are stored inline.

Payload layout (compressed as a whole):

TwinComponentDescriptor descriptors[header.components];
TwinSectorGroup groups[header.groups]; // sorted by sector, unique
uint8_t records[header.instances][header.recordSize];
